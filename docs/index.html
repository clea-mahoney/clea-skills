Add An Approval Step Before Risky Actions

In this course, you'll learn what approval steps are, why they matter, and how to add them to your workflows. This course is for Flowstack admins who build workflows.

Let's dive in.

Why approval steps matter

An approval step isn't a delay, it's a safety net. Workflows run fast — which is great until one runs on the wrong data. One bad run. Hundreds of disabled accounts. No undo.

It's important to note that approval steps leverage Flowstack's seamless notification engine, ensuring the right person always sees the request.

Add the step

  1. Open the workflow in the builder.
  2. Click the + between the trigger and the action you want to protect.
  3. Choose Approval from the step list.
  4. In Approvers, pick the appropriate group.
  5. In Timeout, choose what happens if nobody responds within the time limit: Cancel run or Continue anyway.

For anything destructive, pick Cancel run. A workflow that continues anyway after a timeout is the same as having no approval step.

Test it

Now that you've added the step, it's time to test it. Testing isn't optional, it's how you know the approval works.

Utilize a test user to run the workflow. The approver gets a notification in Slack and email. Click Approve and confirm the action ran. Then run it again and let it time out to confirm the run cancels.

With these steps, you're ready to take your automation safety to the next level.

Add an approval step before risky actions

Some workflows do things you can't easily undo, like disabling user accounts. If one of those runs on the wrong data, it can lock out hundreds of people before anyone notices. An approval step makes Flowstack wait for a person to say yes before the risky action runs.

Add the step

  1. Open the workflow in the builder.
  2. Click the + between the trigger and the action you want to protect.
  3. Choose Approval from the step list.
  4. In Approvers, pick a group that has someone available whenever this workflow runs, such as your on-call group. Anyone in the group can approve. If the group doesn't exist yet, create it first. [Screenshot: the Approval step's settings panel, with Approvers set to the on-call group]
  5. In Timeout, set how long Flowstack waits for an answer. Then choose what happens if nobody responds in time: Cancel run or Continue anyway. [Screenshot: the Timeout setting with a 1-hour limit and Cancel run selected]

For anything destructive, pick Cancel run. A workflow that continues anyway after a timeout is the same as having no approval step.

When the workflow reaches this step, everyone in the approver group gets the request in Slack and email.

Test it

Run the workflow once each way before you turn it on. Point it at a test user account, so the action only touches an account nobody depends on. To keep the timeout test short, set Timeout to a few minutes while you test.

  1. Run the workflow against the test user. Check that the approval request arrives in Slack and email.
  2. Click Approve, then open the workflow's run history and confirm the action ran.
  3. Run it again and don't respond. After the timeout passes, check run history to confirm the run was canceled and the test user wasn't changed.
  4. Set Timeout back to the limit you want in production.

The API, for one person

The Skilljar API relabeled 32 of 33 old courses in one run. It worked, but only from code, so only one person on the team could use it.

Everyone else still copied, pasted, and checked by hand. Two ways of working, and they drifted apart.

The MCP, for the whole team

The Skilljar MCP works in chat, in Cowork, and in code. Everyone could build and check courses the same way, from wherever they worked.

The first full course built through it surfaced three problems:

  • Changes reported as saved sometimes weren't.Every change is checked after it's made.
  • HTML lessons in Skilljar can't add a video later.Every lesson is now a modular lesson.
  • Skilljar rewrites a lesson's HTML when it saves, so checks flagged differences no reader would see.Checks compare the lesson content only.

Where it landed

Human input only for what the MCP can't handle, like lesson length.
